# The example and component generators

`pnpm build-examples` (`scripts/build-examples.mjs`) renders every `.astro` example in `src/component-examples/` and writes its HTML, React, Svelte and Vue files. It refuses what it can't convert: every unsupported construct throws an error that names the file and the construct, and nothing is guessed. The output is checked against the Astro render, never against the generator itself.

## Modules

Each module owns one invariant, and one test enforces it.

| Module                            | Owns                                                                                                                                                                                                                                                           | Invariant                                                                                                                        | Enforced by                                                                                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `scripts/html-tokens.mjs`         | The source-faithful HTML parser on parse5's tokenizer: elements, text and comments with their source slices, `VOID_ELEMENTS` and `BOOLEAN_ATTRIBUTES`.                                                                                                         | `serialize(parseHtml(x)) === x`, and the tree equals parse5's except inside `<select>`.                                          | `tests/unit/html-tokens.test.ts`, and `tests/unit/parity.test.ts` on every render.                      |
| `scripts/example-display.mjs`     | The display model: UA defaults, `core/normalize.css`, `core/utils.css`, the component CSS and `src/styles/example-layout.css`, cascaded by layer, specificity and source order, and which whitespace renders.                                                  | It agrees with the browser's computed `display`, `white-space` and generated content.                                            | `tests/unit/example-display.test.ts`, and `tests/e2e/example-display.spec.ts` on every HTML example.    |
| `scripts/example-encoders.mjs`    | One encoder per target context: `htmlText`, `attributeText`, `markupText`, `jsxText`, `jsxAttribute`, `templateLiteral`, and the decoders.                                                                                                                     | Every value round-trips through the target's own parser.                                                                         | `tests/unit/example-encoders.test.ts`, with 300 seeded fuzzed values.                                   |
| `scripts/example-html.mjs`        | `cleanRender`, which turns the Astro render into the HTML example on the parsed tree, `meaningOf`, which the generator compares before and after Prettier, and `whitespaceRoles`.                                                                              | Formatting never changes what the HTML renders.                                                                                  | `tests/unit/example-html.test.ts`, and `htmlFromRender` throws on a change.                             |
| `scripts/example-ids.mjs`         | Placeholders for `Astro.locals.$id` and their numbering in document order.                                                                                                                                                                                     | Every generated id is `<slug>-<example>-<n>`, unique on the page, and lands in an attribute.                                     | `tests/unit/example-ids.test.ts` and `tests/unit/component-ids.test.ts`.                                |
| `scripts/example-react-props.mjs` | React prop names and kinds from `@types/react` and the component types, and `typeDiagnostics` for generated React.                                                                                                                                             | A prop the types don't have throws; every generated React file type-checks.                                                      | `tests/unit/example-react-props.test.ts` and `tests/unit/build-examples.test.ts`.                       |
| `scripts/example-targets.mjs`     | Which files each example generates, the hand-written ledger `scripts/hand-written-examples.json` and the stale check.                                                                                                                                          | A hand-written file would differ if it were generated, and the ledger only grows with a trailer.                                 | `tests/unit/build-examples.test.ts` and `scripts/check-ratchets.mjs`.                                   |
| `scripts/build-examples.mjs`      | `readExample` (one Astro AST walk), `parseExample`, the React, Svelte and Vue writers, the HTML script rules, the renderer and `generate()`.                                                                                                                   | The same source formatted at any width gives the same tree, and every output is up to date and compiles.                         | `tests/unit/build-examples.test.ts`, `tests/unit/example-whitespace.test.ts` and `pnpm check-examples`. |
| `scripts/build-components.mjs`    | The component compiler: `readComponent` (frontmatter and template of a `.astro` component, and the `model` of its `api.ts`), `toReact`, `toSvelte`, `toVue`, `toTypes` and `generate()`, with `scripts/hand-written-components.json` for the files it refuses. | A compiled port renders what the Astro component renders, and the same source formatted at any width compiles to the same files. | `tests/unit/build-components.test.ts`, `tests/unit/component-contract.test.ts` and `pnpm check-ports`.  |
| `scripts/astro-attributes.mjs`    | The check for quoted attribute values with character references in `.astro` files.                                                                                                                                                                             | Prettier's Astro plugin never changes an attribute's meaning.                                                                    | `tests/unit/astro-attributes.test.ts`, the post-edit hook and `scripts/check-staged.mjs`.               |

## Workarounds

Every workaround for a bug in `@astrojs/compiler`, Astro, parse5 or Prettier's Astro plugin has a repro in `tests/unit/tooling-bugs.test.ts` that fails when a dependency update fixes the bug; the failure names the workaround to remove. The components stay independent of how Prettier wraps their source: `tests/unit/component-formatting.test.ts` renders each one from its source formatted at printWidth 40 and 200.

## Adding support for a construct

- Reject first: throw `unsupported(file, what, target, hint)` with the fix, then make it work.
- A new rule comes with a sample it must flag, and with its line in the root `AGENTS.md` Testing section.
- A list that could be derived (React's value-holding components, the input types React fixes, the custom element tags) is derived in a test, not maintained by hand.
- Run `pnpm build-examples` and commit the regenerated files with the change.
