An Astro or Vue reader fills the close-icon slot and forgets closeButton. The slot only renders inside the button that closeButton adds, so the header shows its title and no button, and nothing reports it. In React, Solid and Svelte the icon is the closeIcon prop, which the types take only with closeButton, so the same mistake is a type error there.

Today, no closeButton

<DrawerHeader>
  <h2>Filters</h2>
  <svg slot="close-icon">...</svg>
</DrawerHeader>

Filters

Show gigs near Lund this weekend.

Console: nothing

With closeButton

<DrawerHeader closeButton>
  <h2>Filters</h2>
  <svg slot="close-icon">...</svg>
</DrawerHeader>

Filters

Show gigs near Lund this weekend.

A dev warning, no closeButton

<DrawerHeader closeButton={dismissible}>
  ...
</DrawerHeader>

Left out: [OPUI DrawerHeader] `close-icon` is ignored without `closeButton`. Set `closeButton` to show the button.

closeButton={false}: no warning, since a header that is dismissible only sometimes is why the types accept any boolean. Astro sees undefined for a left-out prop; Vue casts it to false, so the check reads the raw vnode props.
