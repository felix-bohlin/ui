    With the fix

    Proposed Role and Keyboard support text, with the same menu and a popover="manual" copy. Every claim can be checked in the log: it lists focus moves, arrow key presses and opening and closing.

    Role. A menu is a <menu> of buttons and links, not an ARIA menu. It has no role="menu" or role="menuitem", so screen readers announce a list of buttons, and the keyboard works like it does for any other button. The ARIA menu pattern needs a script for arrow keys, which the library doesn't ship.

    Enter, Space
    On the trigger, opens or closes the menu. Focus stays on the trigger. On an item, activates it.
    Tab
    From the trigger, moves into the open menu: the browser puts a popover opened by commandfor right after its trigger in the focus order. Then moves to the next item, and after the last one, out of the menu to the next element on the page. The menu stays open until Esc or a click outside.
    Shift + Tab
    Moves to the previous item, and from the first item to the trigger.
    Arrow keys
    Do nothing.
    Esc
    Closes the menu and returns focus to the trigger. Clicking outside closes it too. Both only work with the default popover="auto". With popover="manual", close it with the trigger or an item.

    • Proposed: popover="manual" API

    Keep the popover prop with the native values, "auto" (default) and "manual", like Drawer's closedby. The API row says what manual changes, and a Manual section shows a menu that stays open while you pick items. Here only Done closes it; Esc and a click outside do nothing.
