How the React Copy loads its element today and with a static import, as Solid, Svelte and Vue do. The steps are what the browser does on a server-rendered page, in order.

Today, import() in an effect

"use client"
import { useEffect } from "react"

export default function Copy(props) {
  useEffect(() => {
    void import("../../elements/copy.js")
  }, [])
  return <opui-copy ...>...</opui-copy>
}
  1. The server HTML shows the field and the Copy button.
  2. The page's client chunk loads, and React hydrates.
  3. The effect runs and requests the copy.js chunk.
  4. copy.js arrives and defines opui-copy. Only now does the button copy.

Static import

"use client"
import "../../elements/copy.js"

export default function Copy(props) {
  return <opui-copy ...>...</opui-copy>
}
  1. The server HTML shows the field and the Copy button.
  2. The page's client chunk loads with copy.js in it, which defines opui-copy on the server markup.
  3. React hydrates over the upgraded element. A press before this point is held by data-hydrating.

Both stay client components: in a server component, a side-effect import never reaches the browser.
